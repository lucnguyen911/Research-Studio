Privacy Policy

How Research Studio handles research data, external requests and your local workspace.

Data accessed and why

Research Studio uses YouTube Data API Services for public content research. It retrieves information needed to display search results, most-popular listings, competitor channels and uploads, keyword research results, and video or channel details. Depending on the API response, this includes:

  • Video and channel IDs, titles, descriptions, channel handles, country, publication dates, thumbnail URLs, upload playlist IDs, video tags, durations and live-stream indicators.
  • Public raw counts such as views, likes, comments, channel subscribers and video counts where available. Comment counts are metadata; the current client does not retrieve comment text.
  • Search queries, region and language settings, search ordering, result references, collection / expiry timestamps and timestamped raw-count snapshots.

YouTube is the source of applicable API data. The app does not retrieve private channel analytics, revenue, subscriber identities, Google account profiles or YouTube login credentials. The current implementation does not download YouTube video or audio files.

You provide project names and descriptions, saved keywords, research notes, manual video labels, idea titles, tags, source URLs, production status, priorities, project-specific angles and optional published-video links. These support organization and content planning. API titles can prefill idea titles; see the retention limitation below.

RSS / Atom feeds provide article titles, source URLs, publication dates and plain-text summaries. Feed settings, bookmarks and article notes are stored locally. RSS phrase analysis is separate from YouTube API data.

Local settings include theme, language, refresh preferences, storage paths, legal-consent status and its timestamp. Local quota records and rotating diagnostic logs support operation and troubleshooting. The logging code redacts recognized key and token patterns; do not share logs without checking their contents.

API keys, consent and account authorization

The current app uses a user-supplied YouTube Data API key. Google OAuth and Google account authorization are not currently implemented. It does not obtain OAuth access or refresh tokens or request permission to manage your channel.

Before saving a key, the app requires acknowledgment of its legal disclosure covering the YouTube Terms of Service and Google Privacy Policy. Settings allows consent revocation. Revocation blocks subsequent key access for new API requests but does not itself delete the stored key or research data. A request already sent to an external service cannot be recalled.

Using YouTube functionality is subject to the YouTube Terms of Service, the Google Privacy Policy and applicable YouTube API Developer Policies.

External connections and sharing

Local-first describes where the workspace runs and stores its records; it does not mean that all information stays on the device.

  • Google / YouTube: The local backend sends the API key and request parameters, such as queries, video or channel identifiers, region and language, to Google over HTTPS. Google receives the network connection information, including the requesting IP address.
  • RSS publishers: The backend requests feed URLs you configure. Publishers receive those requests and connection information. Public HTTP as well as HTTPS feeds are accepted; HTTP does not encrypt traffic in transit.
  • Thumbnails and external links: Displayed YouTube thumbnails may load directly in the interface from external HTTPS image servers. Opening YouTube videos, channel pages or original articles in a browser contacts the respective sites, whose policies and browser settings apply.
  • Backups: Optional copies are written to a configured folder. If you choose a cloud-synchronized folder, your synchronization provider may transfer those copies under its own terms.

No developer-operated research server, app telemetry, advertising system, data sale or automatic upload of your notes is implemented in the reviewed code. Local user-created notes are not included in the normal YouTube or RSS requests. Any information you deliberately include in queries, feed URLs or correspondence is sent to its destination.

Third parties process requests according to their own policies, including the Google Privacy Policy linked above and the policies of the RSS publishers you choose.

Local storage and security

The default database is %LOCALAPPDATA%\ResearchStudio\data esearch_studio.db. Storage settings can relocate the active data directory. The bootstrap storage configuration normally remains under %LOCALAPPDATA%\ResearchStudio\config\storage.json. The active root also contains logs, configuration and backup folders.

The API key is encrypted at rest using Windows DPAPI for the current Windows user, then stored as an encrypted database value. It is decrypted in memory when needed and sent to Google to authenticate requests. Moving the database to another Windows account or PC may require entering the key again. DPAPI protects the key, not the whole SQLite database, notes, logs or exports. Protect your Windows account and storage devices.

The interface communicates with a loopback-only local backend. Browser localStorage / sessionStorage retain interface preferences and navigation state; these are separate from the SQLite research records. Local security checks and secret redaction reduce risk but are not a guarantee against access by someone who controls your Windows account or device.

Retention, backups and known limits

YouTube API data: The current default cache lifetime is 30 calendar days from collection. Refreshing metadata replaces its collection and expiry timestamps. Individual raw-count snapshots and search sessions have their own expiry. Expired metadata is excluded from normal research reads, then deleted or cleared from referenced records. Linked identifiers and source URLs may remain to preserve your research references.

The cleanup runs at local backend startup and approximately hourly while it remains open, even if automatic refresh is disabled. There is no cleanup process running while the app is closed, so physical removal waits until it starts again. No longer retention period or advanced analytics scope is claimed as approved.

User work: Projects, notes, keywords, manual labels and ideas are retained until you delete them. Purging YouTube metadata does not delete your original notes or linked idea records. RSS articles older than 60 days are eligible for cleanup if not bookmarked, annotated or linked to an idea; retained research items can remain longer.

User backups: The regular Back Up Now and automatic backup paths remove the stored API key and transient YouTube metadata / snapshots before saving a compacted database copy. The code keeps up to seven regular user backups and three pre-restore backups in each managed backup location. Copies, exports and project-recovery JSON files can preserve user work after you delete it from the active workspace.

Important retention limitations

Pre-migration database backups are full database copies, kept by count rather than a 30-day age limit. A safety copy created when overwriting an existing data folder can also retain that folder’s contents. The normal scheduled expiry process does not sanitize these copies.

YouTube video titles can prefill an idea’s editable title. Purging the API cache clears the separate source-title snapshot but does not clear the idea title. Such copied text may therefore remain in ideas, exports, recovery files and backups beyond the API cache limit.

These are unresolved compliance gaps. The app must not be understood as enforcing a complete 30-day retention guarantee across every copy. They require application review and remediation before an audit submission that relies on such a guarantee.

Diagnostic logs rotate by size rather than a fixed time period. User-created exports, externally copied files and recovery JSON have no automatic deletion schedule. Ordinary deletion is not a promise of forensic erasure from disks, operating-system backups or independently synchronized copies.

Your deletion and revocation controls

  1. Clear YouTube data: In Settings, use Clear Cached YouTube Data and confirm. This clears live cached video / channel metadata, snapshots and search sessions, clears API source-title snapshots, compacts the database, and removes database backup files in the active backups/ folder. It preserves the API key, consent, projects, ideas, notes, keywords, manual labels and RSS records. It does not erase copies elsewhere or the copied-title exception above.
  2. Stop API access: Revoke legal consent in Settings and remove the stored API key using the separate key-removal control. Removing a key does not erase research data or revoke the key at Google. To invalidate it at its source, use your Google Cloud project’s credential controls.
  3. Remove research: Use the idea deletion controls, project keyword / competitor removal controls, or delete a project from Project Settings with its required name confirmation. Project deletion preserves shared entities and can preserve shared ideas. It creates a project-recovery JSON file; deleting a project alone does not erase that recovery copy.
  4. Remove all local app data: First note the active data root and any configured backup locations in Settings / storage controls. Close both the interface and local backend. Using Windows File Explorer, remove the Research Studio active data folder, the default bootstrap configuration if separate, and any user backups, exports, old storage roots or external copies you want deleted. This is a manual filesystem procedure; the app has no single erase-everything control. Removing only the app source folder does not erase the workspace.

These controls affect local Research Studio records. They do not delete videos, channels or information held by YouTube. Use YouTube’s own controls for that.

You may review and revoke Google account permissions at Google Security Permissions. This is relevant to authorized applications generally; the current API-key-only Research Studio implementation does not create an OAuth grant there. If account authorization is introduced later, this policy and the consent flow must be updated first.

For questions or assistance, email lucpro911@gmail.com. The maintainer cannot remotely erase a database held only on your PC. Do not send API keys, databases, backups or sensitive notes with your request.

This website and voluntary contact

This static website has no analytics trackers, advertising scripts, third-party fonts, embedded video players, forms, or website cookies / local storage added by Research Studio. When hosted on GitHub Pages, GitHub processes visitor connection information under the GitHub General Privacy Statement. Hosting is distinct from the local app’s storage.

If you email the maintainer, the message includes your email address and whatever information you supply. It is used to answer the inquiry and address project, privacy or compliance matters, and is handled by email providers including Gmail under the Google Privacy Policy. Correspondence is retained while needed to address the matter and any applicable obligations; you can request deletion by email. The maintainer does not need your API key to answer a privacy question.

The app and website do not implement a sale of personal data or behavioral advertising. External services may process information in other countries according to their policies.
